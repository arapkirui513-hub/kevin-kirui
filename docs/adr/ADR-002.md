# ADR-002: Routing Strategy

**Status:** Implemented  
**Date:** 2026-07-24

## Decision

Use the Next.js App Router with static routes and dynamic `[slug]` segments for published case studies.

---

## Context

The portfolio contains:

- `/` – Homepage
- `/work` – Case study index
- `/work/[slug]` – Individual case studies

All published content is known at build time.

---

## Decision

Implement routing using the Next.js App Router with:

- Static routes for the homepage and work index.
- Dynamic routes using `app/work/[slug]/page.tsx`.
- `generateStaticParams()` for build-time generation of all published case study pages.

Current route structure:

```text
app/
├── page.tsx
└── work/
    ├── page.tsx
    └── [slug]/
        └── page.tsx
```

---

## Rationale

1. The routing reflects the existing repository structure.
2. App Router is the current Next.js routing model.
3. Static generation integrates naturally with file-based content.
4. Additional content sections can follow the same routing pattern.

---

## Trade-offs

### Chosen

- File-based routing with static generation.

### Accepted

- Adding new case studies requires rebuilding the site.

### Rejected

- Pages Router, because it is the older routing model.
- Custom server routing, because it introduces unnecessary complexity.

---

## Implementation Notes

- `app/work/[slug]/page.tsx` loads content using `getCaseStudyBySlug()`.
- `generateStaticParams()` uses `getAllCaseStudySlugs()`.
- Static pages are rendered during the build.
