# ADR-001: Content Pipeline

**Status:** Implemented  
**Date:** 2026-07-24

## Decision

Use MDX files with `next-mdx-remote/rsc` for published case studies while maintaining all handbook documentation as standard Markdown files in `docs/`.

---

## Context

The portfolio needs to present:

- Case studies with rich media, interactive charts, and React components.
- Handbook documentation maintained as plain Markdown files.

Content must be version-controlled and maintainable by a single developer.

---

## Decision

Maintain a split content pipeline:

1. Published case studies are authored as MDX files in `content/case-studies/` and rendered at build time using `next-mdx-remote/rsc`.
2. Handbook documentation is maintained as Markdown files within `docs/`.

The implementation uses:

- `lib/case-studies.ts` for loading and parsing case study MDX.
- `app/work/[slug]/page.tsx` for rendering individual case studies.
- `next-mdx-remote/rsc` for MDX rendering.
- `docs/` for all handbook documentation.

---

## Rationale

1. MDX is used where interactive React components provide value.
2. Case studies remain version-controlled alongside application code.
3. No separate CMS or content API is required.
4. The project already uses `next-mdx-remote/rsc`, making the content pipeline consistent with the existing architecture.

---

## Trade-offs

### Chosen

- MDX for interactive case studies.
- Markdown for handbook documentation.

### Accepted

- Content updates require editing repository files.
- New content requires a rebuild and redeployment.

### Rejected

- Headless CMS, because it would separate content from the repository and introduce unnecessary operational complexity.
- Markdown-only publishing, because published case studies benefit from embedded React components.

---

## Implementation Notes

- `lib/case-studies.ts` provides `getCaseStudyBySlug()` and `getAllCaseStudySlugs()`.
- `app/work/[slug]/page.tsx` renders MDX content using reusable components.
- `docs/` contains handbook documentation as Markdown.
